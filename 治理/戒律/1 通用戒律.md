# 1 通用戒律（国法）

> 定稿 2026-09-25 · `AGENTS.md` 里是它的一行版（戒-3：改这里，那边跟着改）。
> 用这个工具的**每个项目**都守，工具自带，属于核心。**项目、模块的规矩只能比这里严，不能放松；打架时这里赢。**

| | 规矩 | 从哪来 |
|---|---|---|
| 通-1 | 没让动的文件不动：不删、不搬、不改名；要挪走的一律进 `回收站/`（有编号、有清单，能还原） | 09-23「删除也不要通过网页删……最后还是全权交给ai处理」；09-25 改：「一些可以用脚本完成的东西，不一定全都要让agent来，比如那个模块的加减之类的，如果模块有文件之类的要出警告，空的就无所谓」 |
| 通-2 | 网页能直接做的（删模块、复活、删存档）先挪进回收站：空的直接做，有文件先警告、人确认；agent 只照人的删除请求用 `move_to_trash` 挪；彻底删掉只在清理页由人点，只删定性过的存档以前进来的，再确认一次 | 09-22 定：能删，但永不静默删；09-25「独立建一个文件夹当缓存空间来装清理的垃圾文件」「存档定性了之后，删除的时候也好删除」 |
| 通-3 | 不打断人：要人判断的写进网页「待你判断」，人攒着一起拍板 | 09-22 定 |
| 通-4 | 项目不依赖工具：把 `索引/` 改个名，项目照常跑 | 09-22「那也算包装……其实也算是一个项目说明书」 |
| 通-5 | 外面的材料只从「外部资料入口」进；工具只挪人点过的 | 09-23「这个应该是默认设计中的模块而不是载荷」 |
| 通-6 | 笔记只增：改和删之前原文先进 `笔记/历史/`；复制过的指令永远不删 | 09-23「但凡是复制了的要留存历史记录」 |
| 通-7 | 做完靠交付，不靠嘴说：agent 不交付（不写怎么验、没验过）就不能标「做完」；交付时每条检查都过了，**默认通过**、直接算做完（标「默认通过」），有没过的检查才等人看；人随时能打回，通过了的也能（打回的回到「在做」）；人在网页上点验收、或在对话里说一句，照旧记成人验收的（agent 照原话记，写明是人说的） | 09-23 定；09-28 放宽（作者：「不用去自动化页交付，我让你执行就可以执行了，那个自动化协议写宽松一点」）；09-30 改成默认通过（作者：「验收一律默认通过」） |
| 通-8 | 数字只来自真跑出来的结果，不编；把握只写高中低，不写百分比 | 09-23 定 |
| 通-9 | 交付前对着作者原话数一遍：技术上对，不等于交付对 | 09-22「为啥很多东西需要我反复交代？」 |
| 通-10 | agent 写进来走 MCP，每条记清是谁写的 | 09-22「真正干活的人是 agent，靠 agent 驱动」 |
| 通-11 | 固定模块 蓝图、戒律、源代码 不能删 | 09-25「这几个不能删」 |
| 通-12 | 核心每改一次，在日志记一条「改了核心」（09-29 起机器记的进 日志/，笔记只放人写的）；固化以后要更高权限才能改 | 09-25「agent和人必须得获得更高的权限才能更改」 |
| 通-13 | 做事按「目标 → 计划 → 戒律」：先在蓝图目标下写一份计划（`治理/计划/<目标>/`，起名 `P<号> · 年-月-日 · 标题.md`），开头写为了哪个目标、守哪些戒律，再动手 | 09-25「我以后做事的流程就是以蓝图中的目标为导向按照计划遵守戒律去实现目标」 |
| 通-14 | 自动答疑只用记录里人说过、定过的，写明用的哪条；查不到就问人，不编 | 09-25 作者选「agent 的问题先自动查」 |
| 通-15 | 自动推进只在两类事上停：彻底删除 / 公开发布（上传、发帖、推送）；改方向（S0、S1、需求、戒律正文——新想法记成想法）。停了不干等：记下来、跳过这件接着做别的。不停但要记：装软件（只从官方来源，记日志、写工具卡）、挪进回收站、要花钱的（agent 付不了：记下来跳过）、改核心（动之前 save_checkpoint 存一档核心，改完日志记「改了核心」）。没有在跑的开工单 agent 自己开（start_work），不用人点；人在网页上叫停过就不自己开，等人再交给 agent 或在对话里说；同一件连续失败到开工单写的次数（默认 2）换一件；圈数到上限停。几个 agent 一起干照 `自动化/协议.md` 分工 | 09-25 定（W1 自动推进）；09-27 晚「改核心」从必停里拿掉、改成先存全量档（作者：「碰核心的就存档就行了，这样可以复原不容易回不去，就全量存档」）；09-27 加「发动」和「装软件」（作者：「所有设备都是绿的才能运转」「它找、写卡、给命令，你点头装」）；09-27 下午「发动」改成开工单「交给 agent」（作者：「左边目录应该是每个自定义清单的一个文件……按照要求把这些交给agent」）；09-30 放宽成现在这样（作者：「自动化协议宽松一点，不要老是让人去确认，只有有需求，蓝图，戒律，验收标准，等等可以一站式自动推进进程」；选了只在「彻底删除、公开发布」「改方向」停、agent 自己从蓝图挑活） |
| 通-16 | 自动化的日志和答疑跟笔记分开：流水账不进人的笔记 | 09-25「自动化要有自己的专属自动化日志和答疑不要跟笔记混在一起」 |
