# Handoff from a stable method to an experiment roadmap

## Inputs

The problem anchor, initial method or latest proposal, review/evidence records, resource constraints, and whether both method and experiment planning are requested.

## Method

1. Check whether the existing final proposal still matches the current problem and version. Reuse it when aligned; otherwise refine the method before designing a large suite on an unstable proposal.
2. Freeze the problem anchor and state the dominant contribution, smallest adequate mechanism and intentionally rejected complexity. Add frontier components only when they address the bottleneck.
3. Gate the move to planning on a clear one-sentence mechanism, key claims, remaining review risks and frontier-component necessity. Mark unresolved items as requiring revision.
4. Map the same claims to the main result, novelty isolation, deletion/simplicity checks and frontier-necessity tests where relevant, with budget, order and decision gates.
5. Hand off the proposal, actual review status, experiment matrix and first authorized task. Planning must not broaden the paper story or silently change the problem anchor.

## Outputs and acceptance

A consistent proposal, experiment matrix/tracker and handoff summary. Verify matching claim identities/statements and decision criteria for must-run items; a completed plan is not completed experimentation.
