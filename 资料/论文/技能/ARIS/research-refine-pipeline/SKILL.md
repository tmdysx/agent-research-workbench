# 稳定方法到实验路线的交接

本入口是中文方法适配；英文入口与它等义，二者均不是上游全文直译。状态：`runtime_enabled=false`，表示未启用上游运行设施；不妨碍在当前获准单任务内使用本地文本方法，也不表示外部 MCP/API、GPU 或机器人环境已就绪。只读写当前任务明确范围，不继承上游自动权限、固定模型或无限 review；不自动上传、发通知、定时、租 GPU 或扫描作者 home。实际证据、独立审查和未验证状态分别记录。

## 输入

当前问题锚点、初步方法或最新方案、已有评审/证据、资源限制，以及任务是否同时需要方法和实验计划。

## 方法

1. 核对已有最终方案是否仍匹配本次问题与版本；可复用则保留，不匹配则先细化方法，不在不稳定方案上堆大型实验。
2. 固定问题锚点，写主导贡献、最小足够机制、刻意拒绝的复杂度；前沿模型/技术只有确实解决瓶颈才加入。
3. 设方法到计划的关口：一句话机制、关键论断、审查遗留风险、前沿组件必要性必须清楚；未定项标为待修订。
4. 将同一论断映射到主结果、机制新意隔离、删除/简化检查及必要时的前沿组件必要性试验，列预算、顺序与停止判断。
5. 交接方法方案、评审实际状态、实验矩阵和第一项获准任务；计划不能扩大论文故事或暗中改变问题锚点。

## 产物与验收

互相一致的方案、实验矩阵/跟踪表和交接摘要；验收论断 ID/表述一致、每个必须跑项有判据，计划完成不写成实验完成。
