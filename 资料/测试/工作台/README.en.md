# 测试 workspace

Datasets may include input samples or manual checks. Keep implementations in Test code. For every run, record inputs, code, command and actual outputs, then store outputs in Results.

The workspace does not run code, invent pass states or infer experiment links from filenames. Link inputs, code and results using explicit paths in each run record. Existing modeling and other materials stay in place.

Documents and configuration are ordinary files shared by the webpage and agents. Saving checks the source revision; conflicts retain your input, and updates preserve the previous file in history. New projects inherit built-in templates rather than working drafts, datasets, notes or run records.
