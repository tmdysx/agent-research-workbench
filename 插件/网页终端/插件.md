# 网页终端

> 插件：不进核心代码，玩家自己装、自己启用（总蓝图 S1-11「玩家自己组装」）。拿掉这个文件夹，核心照常，只是「自动化 → 窗口」那页没了。
> 来自作者 2026-10-02「就不能在网页端展示这个吗？」（选了「网页里直接嵌终端」）；项目 需-23。

## 它做什么

- 「自动化 → 窗口」：上面一排标签，一个标签一个 PowerShell 窗口，能看能打字；「＋ 新窗口」开一个空的；默认并排看（几个窗口同时铺开），「一次看一个」切回标签
- 组织页每个 agent 卡上「开工」：照它的档案（用什么、模型、开工的话）生成开工脚本放进 `索引/开工/`，开一个标签跑它；人也可开启「全自动开工」总开关，由本机外层运行器按岗位接续真实 CLI。默认同时最多 3 个，独立审核和验收不依赖固定 G1；流程见 `使用说明.md`
- 窗口在一个小服务里跑（`server.py`），只关网页不会中止终端；回来接上，看得到最近的输出（每个窗口最多留约 40 万字符，按完整输出块淘汰）。关闭对应终端会中止里面的运行，「关掉网页终端」会关闭全部窗口；停止派发和恢复步骤见使用说明
- 只听本机 127.0.0.1；每个口子要带令牌（应用打开时给的，别的网页拿不到），所以别的网站连不进来

## 任务右侧的观看窗口

自动化面板右侧切换「详情 / 终端」；终端页只附着人明确选择的现有窗口，默认「仅观看」。观看不会输入命令、改变 PowerShell 尺寸、新建窗口或关闭窗口。点击外层面板的「接管输入」后，同一个窗口断开观看连接，再建立输入连接；切换任务或窗口时回到观看。独立「窗口」页仍可并排管理。

窗口记录包含 `agent_code`、`task_key`、`project_root`、`cols`、`rows`。项目路径由终端服务的启动目录确定；员工和任务由开窗调用明确填写。旧窗口没有员工 / 任务关联时显示未关联，不能根据窗口标题或启动命令补成事实。`task_key` 是开窗时明确承接的任务，员工后续接新活时，面板当前任务应读取实时认领，不能把这份初始关联当成当前任务。

### 嵌入协议（给维护者与 agent）

- 页面：原地址后加 `view=1&layout=single&p=<外层页面 origin>`；可选 `attach=<已有窗口 id>`。页面不会自动选最后一个窗口，也不会处理旧 `open` 消息。外层保持一个 iframe，刷新数据只更新选中项，不能重建 iframe。
- 服务握手：`GET /ping?t=...` 返回 `protocol:2` 与 `capabilities.watch:true` 才允许观看。正在运行的旧服务没有此能力时，显示「当前终端服务尚未支持只读观看」，不会自行重启或新开服务。
- 连接：`/ws/<id>?t=...&view=1&v=2`。`view=1` 在服务端拒绝 `i`（输入）和 `r`（尺寸），返回 `denied`；输入模式使用 `view=0`。两种模式沿用既有令牌，不另建员工权限系统。
- 新协议帧：`history` 带 `data / seq / cols / rows`，`output` 带 `data / seq`，`size` 带 `cols / rows`。历史快照和实时输出共用串行发送队列；重连先清空终端显示再回放历史，不重复堆积输出。无 `v=2` 的旧调用继续得到原来的文本流。
- 外层发送 `{type:'terminal-select',windowId,mode:'watch',requestId}` 选窗口；发送 `{type:'terminal-mode',windowId,mode:'control'|'watch',requestId}` 切换输入。观看页同时核对 `event.origin` 和 `event.source===window.parent`；错误来源消息不执行。
- 页面回报 `{type:'terminal-ready',viewer:true,protocol:2,mode:'watch',layout:'single'}`；外层收到 `viewer:true` 不得把旧开窗队列发送给它。每项操作回报 `{type:'terminal-selected',requestId,windowId,mode,ok,error?}`，错误为 `{code,message}`。未选择窗口时 `windowId:null`；切换失败保留真实状态，不冒报已接管。
- `POST /api/terms` 保留原 `title / cmd`，可追加 `agent_code / task_key / project_root`。传入项目与服务启动目录不一致时拒绝；人工和自动开窗使用同一份明确关联。读取窗口、备料和面板刷新不会调用派活或启动员工。

## 装法（Windows；装之前先问人）

先说明要装什么、从哪里来，取得人的安装授权再执行。已有明确授权的同一项操作，引用原记录即可：本项目现有下载的授权见 `工具库/下载/清单.md` 中作者 2026-10-02 的原话；这不等于授权任意升级、安装新工具或替人启用插件。下面是安装说明，本次文档修订没有执行安装、下载或启用。

### 1. 确定后台用的 Python

在本项目根文件夹打开 PowerShell。用**启动后台的同一个 Python**安装和检查，不单独运行不知属于哪个环境的 `pip`。

```powershell
# 启动.bat 在这台电脑优先选 Python 3.12；若你手动用了别的解释器，改为它的完整路径。
$terminalPython = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python312\python.exe'
if (-not (Test-Path -LiteralPath $terminalPython)) { throw '请把 terminalPython 改成启动后台所用的 Python 完整路径' }
& $terminalPython -X utf8 -B -c 'import sys; print(sys.executable); print(sys.version)'
```

确认输出的路径与启动后台的解释器相同再继续。后台的 FastAPI、uvicorn 仍按应用原有安装说明准备；这个插件另需以下两项，许可证都是 MIT。

### 2. 安装 pywinpty 3.0.3

官方来源：[PyPI 的 3.0.3 页面](https://pypi.org/project/pywinpty/3.0.3/)；用途是在 Windows 上开 PowerShell 终端。版本固定为本项目已核实的 3.0.3，已有这个版本就跳过安装。

```powershell
& $terminalPython -m pip install --index-url https://pypi.org/simple/ --only-binary=:all: pywinpty==3.0.3
if ($LASTEXITCODE -ne 0) { throw 'pywinpty 安装失败；保留错误信息，先不要启用插件' }
& $terminalPython -X utf8 -B -c 'import importlib.metadata as m; print(m.version("pywinpty"))'
```

最后应显示 `3.0.3`。找不到适合此 Python 的安装包时，先核对解释器版本和 Windows 架构，记录缺项；不要顺手改版本或安装编译工具。pip 安装包自带的许可证应保留在该 Python 的 `Lib/site-packages/pywinpty-3.0.3.dist-info/licenses/LICENSE.txt`，官方原文见 [pywinpty LICENSE.txt](https://github.com/andfoy/pywinpty/blob/main/LICENSE.txt)。

### 3. 准备 xterm.js 5.5.0 与 addon-fit 0.11.0

先看已有库：本项目 `工具库/下载/xterm/` 已有 `xterm.js`、`xterm.css`、`addon-fit.js`，版本和指纹在下载清单中。三个文件齐全时可直接复用，不需要重下。查找顺序是：先找 `插件/网页终端/lib/`，再找 `工具库/下载/xterm/`；按每个文件分别查找，不是只认某一个目录。

缺文件时，经授权再从官方 npm 仓库取下列**固定版本**。不需要安装 Node.js 或 npm。官方项目是 [xterm.js](https://github.com/xtermjs/xterm.js)；包的身份、版本和许可证可查 [xterm 元数据](https://registry.npmjs.org/@xterm/xterm/5.5.0) 与 [addon-fit 元数据](https://registry.npmjs.org/@xterm/addon-fit/0.11.0)。

| 官方包 | 压缩包内文件 | 放到插件 `lib/` 中的名字 |
|---|---|---|
| `@xterm/xterm` 5.5.0 | `package/lib/xterm.js` | `xterm.js` |
| 同上 | `package/css/xterm.css` | `xterm.css` |
| 同上 | `package/LICENSE` | `LICENSE-xterm.txt` |
| `@xterm/addon-fit` 0.11.0 | `package/lib/addon-fit.js` | `addon-fit.js` |
| 同上 | `package/LICENSE` | `LICENSE-addon-fit.txt` |

以下命令适用于插件 `lib/` 尚无这五个目标文件的情况；发现重名就停止，先核对已有版本，不覆盖别人的文件。Windows 需要自带的 `tar.exe`；找不到时记录缺项，不自动安装新工具。

```powershell
$terminalStage = Join-Path $env:TEMP ('webterm-' + [guid]::NewGuid().ToString('N'))
$terminalXterm = Join-Path $terminalStage 'xterm'
$terminalFit = Join-Path $terminalStage 'fit'
$terminalLib = Join-Path $PWD '插件\网页终端\lib'
$terminalMap = @(
    @{ Source = 'xterm\package\lib\xterm.js'; Target = 'xterm.js' },
    @{ Source = 'xterm\package\css\xterm.css'; Target = 'xterm.css' },
    @{ Source = 'xterm\package\LICENSE'; Target = 'LICENSE-xterm.txt' },
    @{ Source = 'fit\package\lib\addon-fit.js'; Target = 'addon-fit.js' },
    @{ Source = 'fit\package\LICENSE'; Target = 'LICENSE-addon-fit.txt' }
)
foreach ($entry in $terminalMap) {
    if (Test-Path -LiteralPath (Join-Path $terminalLib $entry.Target)) { throw ('已有文件，请先核对：' + $entry.Target) }
}
New-Item -ItemType Directory -Path $terminalXterm,$terminalFit -Force | Out-Null
Invoke-WebRequest -UseBasicParsing -Uri 'https://registry.npmjs.org/@xterm/xterm/-/xterm-5.5.0.tgz' -OutFile (Join-Path $terminalStage 'xterm.tgz')
Invoke-WebRequest -UseBasicParsing -Uri 'https://registry.npmjs.org/@xterm/addon-fit/-/addon-fit-0.11.0.tgz' -OutFile (Join-Path $terminalStage 'fit.tgz')
tar -xzf (Join-Path $terminalStage 'xterm.tgz') -C $terminalXterm
if ($LASTEXITCODE -ne 0) { throw 'xterm 解包失败，停止复制' }
tar -xzf (Join-Path $terminalStage 'fit.tgz') -C $terminalFit
if ($LASTEXITCODE -ne 0) { throw 'addon-fit 解包失败，停止复制' }
foreach ($entry in $terminalMap) {
    if (-not (Test-Path -LiteralPath (Join-Path $terminalStage $entry.Source))) { throw ('包内缺文件：' + $entry.Source) }
}
New-Item -ItemType Directory -Path $terminalLib -Force | Out-Null
foreach ($entry in $terminalMap) {
    Copy-Item -LiteralPath (Join-Path $terminalStage $entry.Source) -Destination (Join-Path $terminalLib $entry.Target)
}
```

两个包都要保留自己的许可证和署名。xterm 的原文见 [5.5.0 LICENSE](https://github.com/xtermjs/xterm.js/blob/5.5.0/LICENSE)；addon-fit 的原文见 [0.11.0 对应发布提交的 LICENSE](https://github.com/xtermjs/xterm.js/blob/f447274f430fd22513f6adbf9862d19524471c04/addons/addon-fit/LICENSE)。

复用应用库时，两份原文分别在 `工具库/下载/xterm/LICENSE`（xterm 5.5.0）和 `工具库/下载/xterm/LICENSE-addon-fit.txt`（addon-fit 0.11.0）；2026-10-03 本轮重新核对，两份文件均已存在，并各自与对应官方发布包的 `package/LICENSE` 逐字节相同，不能把 xterm 的 LICENSE 当成两份。缺少任何一份时，按授权补存对应原文；本次文档修订没有新增库文件，也没有实际执行全新安装。

### 4. 检查，再由人启用

仍在项目根，用步骤 1 选定的解释器：

```powershell
& $terminalPython -X utf8 -B 插件/网页终端/check.py
$terminalCheckExit = $LASTEXITCODE
Write-Output "退出码：$terminalCheckExit"
```

- 输出「能用」、退出码 0：表示当前 pywinpty 可以导入、三个网页资源齐全。
- 输出「还缺：……。装法见 插件.md」、退出码 1：照列出的缺项补齐后再检查。该检查不核对许可证，也不证明真实 agent 已接通。
- 人在「工具 → 外部工具和插件」选「网页终端」，点「检查」，通过后点「启用」。然后到「自动化 → Agent → 窗口」点「打开」（页面提示「网页终端没在跑」）；服务已在跑时会接上已有窗口。组织页的「开工」会启动真实员工，按需要由人操作。
- 没装或没启用时按页面提示处理；不要把空终端、脚本生成或模拟开窗当作真实 CLI 已完成工作。

两项依赖及出处也列在 `第三方许可证.md` 中。
