# 交付自查：对着原话数一遍

**技术验收通过 ≠ 交付合格。** 「说三栏做了四栏」这种错，技术检查一条都查不出来，因为它技术上完全正确。
所以交付之前，**回到用户的原话**，逐条对：

| 查什么 | 怎么查 |
|---|---|
| **数字对不对** | 说三栏就数最终页面上是不是 3 行——**数呈现出来的，不是数代码里有几个对象** |
| **范围对不对** | 说不做 X，就没在 X 上花力气；说只要 A，就没顺手加 B、C |
| **内容该不该在里面** | 模板、工具里**不放用户的真实数据**，用占位；不去翻用户没让看的文件 |
| **动了不该动的没有** | 没说要改的文件，一个字节都没碰；要改的都说清楚了改了什么 |
| **名字对不对** | 用户起的名字原样用（比如「外部资料入口」就不写成「投递」） |
| **位置对不对** | 用户说放哪就放哪（比如「放设置后面」） |

**对不上就别拿出来。** 先改，改完再对一遍。

## 汇报时

- 用人话，术语放括号里；用户看不懂＝这次输出无效
- 先说做成了什么、用户能亲眼看见什么，再说替他定了什么（可以推翻）、还差什么
- 没验过的就说没验过，不要写「应该没问题」
