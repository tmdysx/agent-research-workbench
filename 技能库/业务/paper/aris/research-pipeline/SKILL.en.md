# Research Stages and Handoff Reference

This is a local adaptation of pinned upstream methods. Follow the current goal, approved plan, and file scope; put actual materials/results in the author-selected workspace, not built-in folders.

## Inputs

Research direction, requirements/acceptance, materials, actual stage, budget, approved plan, and gaps.

## Workflow

1. Read goals, requirements, and latest handoff; mark stages not started/in progress/waiting for evidence/complete using artifacts/checks rather than summary wording.
2. Route through idea discovery, feasibility/experiment bridge, research assessment, writing handoff, and manuscript preparation; give the next task, inputs, outputs, and evidence gate for each.
3. Execute the authorized stage through platform plan review, permissions, and stopping conditions; missing upstream juries/oracles/helpers are gaps, not replaced by self-certified independence.
4. At stage end retain evidence, failures, changes, and open issues in a compact handoff; separate external wake-up mechanisms from scientific judgment.
5. Advance using checked inputs; record author decisions for changed direction/budget/new resources while continuing independent authorized work.

## Outputs

research-route.md, stage-evidence.md, and handoff.md linking real tasks/plans/deliveries without a second runtime source of truth.

## Acceptance

- Stage completion has concrete artifacts/checks accessible to the next worker.
- Undeployed upstream automation/reviewers/models are not shown as running.

## Continue When

Advance only the next task supported by permissions/materials; record missing roles/evidence as waiting reasons.

## Tools and Status

Reading/textual methods require no runtime installation or model API. Actual business actions are carried out by the current agent and authorized tools.

Bundled guidance does not prove installed dependencies or validated runtime. Reading/copying a skill does not enable automation, create employees, rent resources, or publish outputs.

ARIS timer loops, hooks, MCP calls, and cloud notifications remain reference material, never default actions of this entrypoint.

## Stage evidence and resumption

1. Bind each stage to full goal/requirement/task provenance, approved P plan, input versions and artifact locations; keep awaiting acceptance, completed and failed distinct.
2. Resume by reconciling latest K/J/H and actual files; review written but unaccepted output first, preserve failed-run output, and avoid repeating verified completed steps.
3. Scientific stage completion needs its evidence gate; platform delivery acceptance checks construction and is recorded separately.
