# 自动化科研交互界面 · 给 agent 的用法

这个项目用一个本地网页加一套文件来管：**人定方向、看成果，不满意时打回；你（agent）干活并如实检查，系统按交付策略验收。** 它专门防两件事：长程任务做着做着**跑偏**；换一个 agent 就**接不上**。所以照下面做——你留下的东西，决定下一个 agent 能不能接上你。

项目根 `AGENTS.md` 是规矩的正本；这份技能跟它冲突时听 `AGENTS.md`；人这次明确说的，比这两份都优先。

## 一、进门先做这 5 步

1. 读项目根 `AGENTS.md`：规矩、东西在哪、**技能目录**（用得上的技能先读）
2. 读最新的交接单：`自动化/交接/` 里最新那张（没有就跳过）
3. 看全貌：接了 MCP 就调 `get_overview`；没接就读 `治理/目标/S0 终极目标.md`，再看 `自动化/开工单/` 里「状态: 在跑」的那张
4. 读人的话：MCP `read_notes`、`read_log`；没接就看 `笔记/` 里各本最近的几条，和 `笔记/日志/` 最新那个月文件的末尾
5. 人问你的先答，再开始干（`get_overview` 里「你问 agent」那一段，用 `answer_person` 答）

## 二、东西在哪

| 位置 | 放什么 | 谁能改 |
|---|---|---|
| `治理/目标/` | `S0 终极目标` · `S1-1 …` 各份；每份里的 S2 表是一件件事和它的状态 | 方向人定；S2 状态你只能写「在做」「等工具」「等你」，做完靠 `deliver` 交单 |
| `治理/需求/` | 需求：要什么功能、要什么效果 | 人定；你可以提候选 |
| `治理/戒律/` | 规矩：`1 通用` · `2 项目` · `模块/<模块>.md` | 人定 |
| `治理/任务/` | 模块的施工单（一件件事、为了哪条需求、怎么验、状态） | 你按授权写 |
| `治理/计划/<目标>/` | 每次的计划 P、设计参考 R | 你写 |
| `资料/<模块>/` | 业务材料；`技能/SKILL.md` 是这个模块专属的做法 | 按模块规矩 |
| `笔记/` | 人写的笔记 | **只读，别改别删** |
| `笔记/日志/` | 机器记的：网页上的操作、agent 做的事（志-0001…） | 程序和你，只增 |
| `自动化/` | **`协议.md`（怎么报到、自己开工、几个 agent 怎么分工）** · **agent 档案 `agent/`（G…）** · 开工单 K · 交付单 J · 运行日志 · 答疑 Q · **交接单 H** | 你照规矩写 |
| `技能库/` | 通用技能（这份就是） | 可以加新的 |
| `工具库/` | 工具卡 T：外部程序怎么查、怎么调 | 缺工具从官方来源装上、写一张卡、记日志 |
| `插件/` | 插件：重活，人点了才启用 | 别替人启用 |
| `存档/` · `回收站/` | 存档 C · 挪走的东西 X（能还原） | 程序管 |
| `backend/` `模板.html` 等 | 程序本身（核心） | 改前先存一档核心；改网页前先读项目根 `DESIGN.md`（长什么样） |

## 三、做事：目标 → 计划 → 戒律

**自动推进、几个 agent 一起干，照 `自动化/协议.md`**（正本）。先 `register_agent` 报到，再 `my_profile` 读岗位、工种、范围、暂停状态和施工计划要求。调接口使用自己的档案身份，不借别人的名字；权限由人配置，不能给自己扩大范围。

外层运行器通过 `next_action` 取一项明确动作，再启动本机真实 Codex CLI 执行。平台不调用模型 API。每个模型轮次只完成这一项动作；返回等审、旧流程等验收、等锁、无任务或停止时结束轮次，让外层程序等待，不在模型中执行睡眠、反复查询或持续空转。本项目新交付按下述策略自动验收或返工。手工接入仍可用兼容的 `next_task`，同样遵守计划、岗位和认领要求。

没有固定 G1 特权：需要审核的计划由有授权的另一位审核员审，缺岗位明确报告，不能自行免除审核或伪造通过。同一任务、模块和核心仍遵守已有认领与锁；本机 git 记录不推送。

本项目 `自动化/交付策略.json` 为 `{"version": 1, "mode": "checks-pass"}`：`deliver` 的检查列表必须非空，每一项 `ok` 严格为布尔值 `true` 才自动验收通过，不等另一个验收岗位或人逐张确认。失败、未测、缺字段、字符串或数字不算通过，会打回「在做」供修复、实际复验后重交；空检查拒绝交付。配置畸形或含链接时写单前拒绝，不能降级放行。人打回时停下推进该件，按理由重做。没有此配置的项目保留原独立或人工验收流程，已有记录按历史读取。该策略不免除施工计划审核、岗位范围、认领、核心锁、暂停和原停止条件，也不启用员工。

1. 找到这件事属于哪个目标（S1-x，或某个模块的任务）、为了哪条需求
2. **先写计划**：档案要求审核时，按 `next_action` 的任务调用 `submit_execution_plan(goal, sub, text, files, revision)`；正文写目的、方法、戒律、工具和怎么验，`files` 明确本次修改范围。修订先 `get_execution_plan` 读最新版本；另一位审核员用 `review_execution_plan(code, ok, why, revision)` 审读取到的版本。未审不施工，扩大范围或改正文需重新审。获准的正式计划仍按 P 号和日期放在 `治理/计划/<目标>/`；交付引用这一份。没有启用审核的旧流程仍先写计划，不能把兼容模式当成绕过档案权限的办法。
3. 进哪个模块，先读它的戒律（`治理/戒律/模块/<模块>.md`）和它的技能（`资料/<模块>/技能/SKILL.md`，有的话）；接了 MCP 的用 `get_governance(kind="module", key="模块名")` 一次读到它的需求、戒律、任务、计划（通用模块的 key 照 `get_overview` 返回的写，别猜）
   - 编号会重：「需-1」「S2-1」在不同来源里都有，引用写全来源，比如「文献 需-3」「项目::需-1」
4. 动手；只动计划里写到的文件；要挪走东西进回收站（MCP `move_to_trash`），别直接删
5. 照「怎么验」自己验，结果照实写（数字只写真跑出来的）
6. 交付：MCP `deliver`（交付单进 `自动化/交付/`），填写实际检查、产物和获准计划。本项目检查全过自动验收做完，失败自动返工；成功和失败交付都正常记账并释放任务与核心锁，下一轮按现有准入重新认领。人打回的先按理由修复。无配置时由原系统和档案决定验收流程，不能自己标「做完」，不能把没跑的检查写成通过。
7. 改核心（`backend/`、`模板.html`、界面脚本、启动器）前先 `claim_task("核心")` 拿锁（一次一个人，交付时自动放），再 `save_checkpoint` 存一档（只存核心：程序和规矩，不带资料；只留最近 10 档，多的自动丢），改完记一条日志「改了核心」
8. 有疑问先查旧答案（MCP `find_answer`，或翻 `治理/` 和问答页）；查不到再问人（`ask_human`，或写进交接单「等人定的事」），先做不依赖答案的部分

## 四、改治理正文（目标、需求、戒律、计划）

- 接了 MCP：`read_governance_document(path)` 拿到正文和版本号 → 改 → `write_governance_document(path=返回的 save_path, text=完整正文, revision=原样传回的版本号, reason=为什么改)`。提示冲突就重新读、把人的新内容合进去，别盲目覆盖
- 没接 MCP：直接改那个文件；改前先读最新的，别把人刚写的整份盖掉
- 方向（S0、S1、需求、戒律）只有人能定。人没让改的新想法，先记成想法（`add_idea`，或在 `资料/想法/想法.md` 表里加一行）
- 老项目还没把目标、需求搬进 `治理/` 的，照旧路径读；只有人明确要求时才迁移（先存一档，再 `migrate_governance`），普通接手不迁移

## 五、记录写哪（别混）

| 要记的 | 接了 MCP | 没接 MCP |
|---|---|---|
| 做了一件事、改了核心、交接 | `add_log(text, kind)` | 在 `笔记/日志/<年-月>.md` 末尾加：一行 `## 志-<下一个号> · 年-月-日 时:分 · agent:你的名字 · 什么事 · 模块`，下一行写内容 |
| 自动推进的每一圈 | `report_run` | 写进 `自动化/日志/` |
| 交付 | `deliver` | 照 `自动化/交付/` 里已有交付单的样子写一张 |
| 要问人 | `ask_human` | 写进交接单「等人定的事」 |
| 人的笔记 | `read_notes`（只读） | 只读 |

## 六、走之前：写交接单（最要紧）

`自动化/交接/H<号> · 年-月-日 · 你的名字.md`，号接着最大的往下数。照这个样子：

```markdown
# H3 · 2026-10-01 · codex

- 做了什么：为了哪条需求 / 哪件 S2，一件一行
- 改了哪些文件：列路径；新建的、改的、挪进回收站的分开写
- 验了什么、实际结果：跑了什么、点了什么，结果原样写（比如「测试 110 passed」）
- 没做完的：做到哪一步停的、为什么
- 没验证的、有风险的：没测到的地方、可能出问题的
- 下一步建议：下一个 agent 接着做什么，按先后
- 等人定的事：要人拍板的，写清几个选项
```

接了 MCP 用 `write_handover(text)` 留这份交接；运行器状态按实际情况用 `report_employee_runtime(state)` 更新。下一个 agent 进门先读。说明文档与模拟测试不代表真实 CLI 整链已经验收，交接单须分开记哪些跑过、哪些没有。

## 七、不能做的（详细见 AGENTS.md）

- 没让动的文件不删、不搬、不改名；要挪走进回收站
- 不交付就不标「做完」，检查结果照实写（没过就写没过），不编数字
- 只在这两类事上停：彻底删除、公开发布（上传、发帖、推送）；改方向（S0、S1、需求、戒律正文）。停了不干等，换一件接着做
- 装软件只从官方来源，装了记下来；要花钱的你付不了：记下来跳过
- 别人领着的件、别人的模块、别人拿着核心锁时的核心文件：不碰
- 不改人的笔记；方向和规矩不擅自改

## 各家 agent 怎么接

- 都先读 `AGENTS.md`（Claude Code 经项目根 `CLAUDE.md` 自动读到；别家不自动读的，让人第一句话叫你读它）
- 能接 MCP 的：接本项目的 research-console——在项目根运行 `python backend/mcp_server.py`（项目根 `.mcp.json` 是现成的写法，别家照这条命令配）
- 接不了 MCP 的：照上面「没接 MCP」那一栏直接读写文件，一样能接手

## 只读工作包与网页删除记录

源代码目录的编程工作台和MCP `get_work_package(goal, sub, plan_code, skill_ids, lang)`读同一工作包。引用包含来源、范围和原编号，别用裸需/S2号猜关联。返回原文、当前有效批准计划及允许文件、分层戒律、所选技能、来源版本、实际交付和缺项。包是只读材料，不授予施工权限，不自动领活/开窗/安装；执行仍遵守原报到、认领、独立审计划与核心锁。快照不一致或来源无法核对时重新读，不把不完整包当成批准。所选技能仅项目正本，不宣称已探测安装或真正运行。

人在网页文件阅读页删除，会移入现有回收站并生成X编号；`回收站/清单.md`记录原位置、当前保存位置、来源、原因、操作者和时间，`笔记/日志/`另有删除文件操作，MCP `read_log`可读。通过同一清单的实际状态判断在回收站、已还原或已彻底删除；日志中的“当时在回收站”是发生时的事实，不代替当前状态。人的笔记与历史、存档/归档副本、索引、回收站、目录、符号链接和目录联接不能在阅读页删除。不要据此自动扩大agent删除权限，仍仅照人的明确删除请求。


## 文件内置与存档联动

用户在阅读页点小锁，是声明该文件以后随所选模块进入新项目，不是禁止编辑。原文件不迁移；根目录 `内置标记.json` 是v1相对路径名单，网页/MCP `get_builtin_files(path="")` 同源读取，操作日志仍在笔记/日志。已有内置目录与核心继续默认携带；不要改为扫描并带走所有业务材料。
统一入口为“设置 → 内置”，存档模块没有内置管理入口。长期名单由小锁管理，自定义携带弹窗的业务/额外选择仅用于本次新建；未选模块不被标记反向补回。复制前核查缺件/路径；子代名单仅保留实际复制文件。
全量存档继续保存未标记材料；历史名单来自真正存入的标记正本。恢复仅按用户已授权的范围进行，预览包含内置差异；MCP确认时原样回传 `builtin_revision`，过期则重新预览，不自动覆盖。局部恢复不抹去无关标记，旧档未知不等于空名单；笔记/计划/日志保护和冲突保留继续沿用。内置名单不是索引数据库，agent不能靠改它绕过链接、缓存或记录保护。
